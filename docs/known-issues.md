## 1. 枪械在铁砧修复会越修越贵（**已有原版解法：砂轮**）

**影响**：中。枪械只有铁砧这一条修复路径（`GunItem.isValidRepairItem`），
而原版铁砧每次操作都会给物品的 `REPAIR_COST` 组件 +2，花费按 2^n 量级上涨，
修几次之后超过 39 级，铁砧显示 "Too Expensive!" 拒绝。

### 关键：砂轮能重置惩罚（用户提醒，已确认是原版机制）

原版 `GrindstoneMenu` 在生成输出时会把 `REPAIR_COST` 清掉。所以玩家的解法是：

```
枪修太贵了 ⇒ 把枪单独放进砂轮 ⇒ 取出来（惩罚清零）⇒ 回铁砧继续便宜修 ✓
```

而且对本 mod 更有利的一点：**砂轮只会剥掉原版的 `ENCHANTMENTS` 组件，
不会碰 mod 自己存在 `CustomData` 里的附魔（`ScEnchants`）** ⇒ 过砂轮不会丢枪械附魔。

**⇒ 所以这不是"永久报废"，而是"玩家不知道要过一遍砂轮"** —— 性质从设计缺陷降为**信息缺失**。

### 仍然存在的轻微痛点

- 每修几次就要过一趟砂轮，操作重复；
- 玩家不知道这个技巧，会以为枪废了（这正是最初被报上来的原因）。

### 候选方案（现在优先级都下调了）

| 方案 | 做法 | 代价 | 评价 |
|---|---|---|---|
| **① 什么都不做** | 靠玩家自己发现砂轮 | 0 | 可以接受，但新玩家仍会误解 |
| **② 信息层**（推荐） | 在枪的 tooltip 里加一行：修太贵时提示"放进砂轮可重置修理成本" | 低，不改玩法 | **最贴合"这只是一个不知道的技巧"** |
| **③ 维修条目说明** | 写进整合包任务书 / 成就描述 | 0（包层） | 与 ② 互补 |
| **④ 周期性清 `REPAIR_COST`** | 每 40 tick 扫背包清理（原方案 A） | 每 tick 约 40 ns（0.0001%） | 有效但**抹掉了砂轮这一步玩法** |

### 结论

优先 **②（tooltip 提示）**；④ 保留为可选项，交给配置开关决定。
不要再把它描述成"装备会永久报废"——那是错的，砂轮能救。

## 2. 机瞄相机骨骼会有固定偏移

**影响**：中（只影响用了相机骨骼的枪；原版 141 把不受影响）。

1.20.1 的 `GUN_DEFAULT_ORIGIN` 与移植版不同（字节码里能看到 `8.0` 常量），
而 `getCameraBone` 用的是写死的常量，加上骨骼分支绕过了原路径的补偿
（`+0.6059` 等），叠加起来表现为"相机比机瞄低约 2 格"。

**方案**：把骨骼分支**降级为兜底**（有 `ironSight.camera` 数据时优先用数据），
这样已发布行为完全不变；自定义枪改用数据键定位。

## 3. Create 动力合成与枪械工作台的材料不一致

**影响**：中（有 Create 的整合包里能绕过蓝图与部分材料）。

实测：137 把枪两套配方都有，其中 **90 把不一致**——22 把缺蓝图（古典/边疆可接受），
87 把材料不同，其中 78 把是"动力合成少料"（缺枪管、框架、木板、等级金属）。

**状态**：**暂不修**。用户判断"AI 生成配方布局精确度不够"，应由人工改。
需要时用只读脚本输出"哪把枪少了什么"的清单即可。
