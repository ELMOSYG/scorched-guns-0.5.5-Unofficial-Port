## 本版重点：三个「进不去游戏 / 进不去存档」的问题全部修掉

### 1. 雷电池接入其他模组的能源网络会让服务端崩溃、存档无法进入

雷电池在自己的 tick 里主动把电「推」给相邻方块。`Create: New Age` 的电网在 `insert` 里
**正在遍历自己的成员表**，于这次推送中重入，抛出 `ConcurrentModificationException`，
服务端 tick 直接崩掉 —— 而雷电池每 tick 都跑，所以一旦接线，**存档再也进不去**。

修复分三层：

- 不再向 `create_new_age` 命名空间的方块推送能量（从根上不进入对方的迭代）；
- `LightningBatteryBlockEntity` 对这次推送加异常兜底（其它模组出现同类情况时不会带崩世界）；
- **`Caps.ifPresent` 内部统一兜底** —— 所有「推能量」的方块一次覆盖，且保持方法签名与调用点不变，
  因此重定向 `Caps.ifPresent` 的第三方 mixin（例如女仆兼容的 `PolarGeneratorBlockEntityMixin`）照旧生效。

> 顺带一提：这个崩溃在**原版 0.5.5（1.20.1）里也存在**，只是本版把它修掉了。

### 2. 专用服务器上看不到弹孔

弹孔是客户端粒子：服务端发出命中消息，客户端在**收到消息的位置**取方块贴图。命中消息可能
**早于区块数据**到达客户端，而旧代码把「区块还没加载」读成「这里是空气」，当场把粒子删掉 ——
所以单人正常、专用服务器上永远看不到弹孔。现在区块未加载时不再删除粒子，并在区块到达后
重新解析贴图。

### 3. 安装环境缺少 Polymorph（或多态合成版本不符）时模组加载失败

合成台的配方选择器需要 Polymorph。旧实现把 Polymorph 的类**直接写在带 `@EventBusSubscriber`
的类里**，而模组加载器在**扫描事件订阅者**时就会解析这些类型 —— 运行期那句
`if (!POLYMORPH_LOADED) return;` 根本来不及执行，于是缺少该类时：

```
java.lang.NoClassDefFoundError: com/illusivesoulworks/polymorph/api/client/base/IRecipesWidget
  ⇒ 模组加载失败 ⇒ 游戏进不去
```

现在 Polymorph 相关代码被隔离到一个**不带注解、只通过反射加载**的类里，异常被捕获并记录：
**没装 Polymorph 只会少一个配方选择器，游戏照常进入。**

## 其它修复

### 4. 弹药计数器（Scrapper / Birdfeeder / Repeating Musket / Triquetra）

换弹时弹匣骨骼会一格一格地抽搐，装填完成的一瞬间还会闪回空位。原因是**同一根骨骼被两套系统
同时驱动**：换弹动画本身在驱动它，而弹药计数也在按 `AmmoCount` 喂位置。现在换弹期间（含收尾动画）
不再用弹药数驱动骨骼，完全交给换弹动画，装填结束后立刻恢复。

### 5. 族群克制对某些实体失效

`MobType.of(...)` 原先只看实体类型标签，而标签是按**实体类型**匹配的 —— 实体类型不会因为装备
而改变。于是「戴上僵尸头的试验假人」永远吃不到亡灵加成。现在判定顺序是：

1. **先问实体自己**（反射调用 `getMobType()`，按类缓存、无编译期依赖）；
2. 再退回实体类型标签。

顺带好处：任何**在运行时改变自己族群**的实体（试验假人、以及其它模组的同类实现）都能被正确识别，
近战、光束与附魔加成同时受益。

### 6. 弹丸优势同样失效

枪械的「优势」（例如高能子弹对亡灵 1.75 倍伤害 + 2 秒点燃）走的是另一条判定，同样只看实体类型标签。
现在它也**先问实体自报的族群**，再退回标签。

## 新增

### 7. 全自动光束 / 连发光束

`FireMode` 里其实**早就定义了** `automatic_beam` 与 `beam_burst`，但从未注册 —— 于是写进数据也会被
静默当成半自动，看上去像「模组只支持半自动光束」。本版把它们补注册，并把光束判定统一为
「光束家族」，同时给自动光束加上脉动：两次开火之间会结束当前段落，按住扳机时是一段段短光束，
而不是一条不断的光。

数据写法（枪的 `fireMode`）：

```json
"fireMode": "scguns:automatic_beam"     // 全自动光束：按射速反复射出一段段光束
"fireMode": "scguns:beam_burst"         // 连发光束
```

光束模式需要的光束字段见 `docs/scguns-mechanics.md`。

**本版没有改动任何枪械数据** —— 以上模式是否使用、用在哪把枪上，由数据包或附属自行决定。

### 8. 机制参考文档

新增 [`docs/scguns-mechanics.md`](docs/scguns-mechanics.md)：开火模式与注册状态、装填类型的真实
语义（`single_item` 指「用单个物品装满整个弹匣」，不是逐发装填）、光束字段、弹丸优势系统、
族群判定、数据包覆盖方式，以及一份**「定义了但未启用」清单**（避免把设定当 bug 修掉）。

### 9. 术语

`burst` 的统一译名改为「**连发**」（一次扣扳机打出多发，如 M16A2），与枪械 mod 的惯例一致；
描述玩家行为时仍用「点射」。
