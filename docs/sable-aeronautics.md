# Sable 与 Create: Aeronautics 兼容说明

Sable 会把方块结构变成**子世界（sub-level）**：结构可以整体平移、旋转，而结构内的方块实体仍然
持有**世界坐标**。所以兼容的关键只有一条规则：

> **世界坐标直接用；方块内部的偏移（枪口、射线起点）必须过 `PhysicsStructureHelper` 转换。**

这条规则弄反，就会出现"在物理结构上炮塔不转、索敌错"这类现象——那是另一个移植版反馈的问题。

---

## 一、我们的实现

| 组件 | 位置 | 作用 |
|---|---|---|
| 静态桥 | `compat/SablePhysicsBridge` | 反射拿到 `SubLevelContainer` / `SubLevel` / `LogicalPose`，提供世界↔局部变换与冲量 |
| 工具层 | `util/PhysicsStructureHelper` | `toWorld` / `toLocal` / `normalToWorld` / `applyShotImpulse` / `applyPunchAt` |
| 加载标志 | `ScorchedGuns.sableLoaded`、`physicsStructuresLoaded` | Sable 或 Valkyrien Skies 加载时置位；其余逻辑据此降级 |

**没有 Sable 专用 mixin。** 全部走静态桥：签名在编译期检查，Sable 没装时 `toWorld` 返回 `null`，
调用方回退到未变换的坐标——不会因为反射字段改名而静默失效。

## 二、支持矩阵

| 功能 | 状态 | 说明 |
|---|---|---|
| 炮塔索敌（搜索框、距离） | ✅ | 用 `worldPosition`（世界坐标），无需变换 |
| 炮塔枪口位置 | ✅ | `toWorld(worldPosition, muzzleLocal)` |
| 炮塔瞄准（pitch/yaw） | ✅ | 目标经 `toLocal` 回到炮塔自身坐标系后再算角度 |
| 炮塔射击方向与弹道 | ✅ | 发射点用世界坐标，弹道本身在世界空间 |
| 敌方炮塔（Enemy Turret） | ✅ | 同上，四类炮塔共用 `TurretBlockEntity` 逻辑 |
| 枪弹推动物理结构 | ✅ | `applyShotImpulse`，力度与自旋上限可配置 |
| 光束武器（激光）落点 | ✅ | 世界坐标直接使用 |
| 结构内机器（压机/粉碎/炮塔模块） | ✅ | 只看方块本地状态，不依赖世界位置 |
| 玩家在结构上开火 | ✅ | 玩家坐标本身就是世界坐标 |
| 结构移动时炮塔朝向更新 | ✅ | 每 tick 用当前 pose 重算 |

## 三、游戏内验证清单

放到一艘飞行器（或 Sable 测试结构）上，逐条打勾：

1. 放一座**普通炮塔**，装玩家索敌模块 → 目标在结构侧后方时枪口能转过去
2. 结构**旋转 90°** → 炮塔仍指向目标（不是指原来方向）
3. 结构**上升/下降** → 俯仰角跟着变
4. 开火 → 子弹从枪口出（不是从结构原点出）
5. 子弹打在**另一个**结构上 → 那个结构被推动、且不会无限自旋
6. 放**敌方炮塔** → 索敌与旋转同样正确
7. 结构移动时打开炮塔 GUI → 配置界面不崩溃
8. 拿掉 Sable 进游戏 → 以上功能全部退回主世界行为，无报错

## 四、已知未覆盖（不影响上述功能）

| 项 | 说明 |
|---|---|
| 结构内的**生物 AI** 寻路 | 由 Sable 负责；我们未额外处理 |
| 结构**跨维度**移动 | 未测试 |

## 五、给未来的自己

改炮塔或任何"从方块位置发射东西"的代码时，先问一句：**这个坐标是世界坐标还是方块内偏移？**
- 世界坐标：直接算
- 方块内偏移：`PhysicsStructureHelper.toWorld(...)`
- 世界 → 方块内：`toLocal(...)`

把搜索框、距离比较改成局部坐标会让索敌静默失效——这正是我们在另一个移植版里看到的现象。
